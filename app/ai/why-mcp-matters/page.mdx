Every agent eventually hits the same wall: the model is brilliant in a sandbox and
useless the moment it needs to read a file, query a database, or call an API. For a
while we each solved this the same way — bespoke glue, one integration at a time. The
**Model Context Protocol (MCP)** is the bet that this glue should be a protocol, not a
pile of one-offs.

## The shape of the problem

Before MCP, every tool integration was an N×M problem: every agent had to learn every
tool, and every tool had to be wrapped for every agent. MCP turns that into N+M — tools
expose one server, agents speak one client.

![A diagram showing an LLM agent talking to a single MCP server, which fans out to a filesystem, a database, and an external API](/ai/why-mcp-matters/diagram.svg)

## What it actually standardizes

MCP is deliberately small. It specifies how a client and server exchange three things:

| Primitive | Who controls it | Example |
| --------- | --------------- | ------- |
| Tools     | Model-invoked   | `read_file`, `run_query` |
| Resources | App-controlled  | A file's contents, a row set |
| Prompts   | User-selected   | A reusable "summarize this PR" template |

That's most of it. The protocol is transport-agnostic (stdio, HTTP) and leans on JSON-RPC,
so the surface area you have to trust is refreshingly thin.

## A minimal server

Here's the entire shape of a tool-exposing server — the boilerplate disappears and you're
left describing capabilities:

```typescript
import { McpServer } from "@modelcontextprotocol/sdk/server/mcp.js";
import { z } from "zod";

const server = new McpServer({ name: "notes", version: "1.0.0" });

server.tool(
  "search_notes",
  { query: z.string().describe("full-text search query") },
  async ({ query }) => {
    const hits = await db.search(query);
    return { content: [{ type: "text", text: JSON.stringify(hits) }] };
  },
);
```

## Does the N+M math hold up?

The interesting claim is about integration cost. If you have `A` agents and `T` tools, the
bespoke approach scales as `A × T`; MCP scales as `A + T`. Plotted, the divergence is
stark even at small numbers:

## Where it still bites

It isn't free. A few things to keep in mind:

- **Auth and trust** — an MCP server is code you're handing tool access to. Treat it like
  any dependency.
- **Latency** — every hop is a round trip; chatty tools punish you.
- **Discovery** — the spec tells a client *how* to call a tool, not *whether* it should.
  Tool selection is still the agent's hard problem.

## So, why does it matter?

Because the ceiling on agents was never the model — it was everything the model couldn't
reach. MCP doesn't make agents smarter. It makes the world they act on *plug-compatible*,
and that's the part that compounds.
